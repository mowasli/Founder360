# Founder360 AI

منصة محلية لتشخيص الشركات الناشئة وتطويرها، مبنية على الحزمة المرفقة: **20 محورًا، 100 مؤشر، و140 سؤالًا عربيًا وإنجليزيًا**. تشمل حسابات مستقلة، أدلة خاصة، رحلة متكيفة، محركًا ماليًا، تقريرًا وخطة متابعة، ولوحة برنامج وصلاحيات مرشدين.

**حالة التسليم:** مشروع يعمل محليًا مع اختبارات وبيانات اصطناعية. لم يُنشر على موقع الحاضنة. لا تدّعي هذه النسخة جاهزية إنتاجية نهائية، ولا اتصالًا حيًا بنماذج أو بحث سوقي لم يُختبر. راجع [حالة القبول](docs/ACCEPTANCE_REPORT.md).

## ابدأ من هنا

المطلوب: Python 3.12 وNode.js 22 أو أحدث. الملفات المبنية موجودة في `dist/`؛ تثبيت Node لازم لتعديل الواجهة وإعادة بنائها. Python ضروري لتشغيل الخادم.

### Windows / PowerShell

افتح الطرفية داخل مجلد المشروع بعد فك الضغط:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
npm ci
npm run build
Copy-Item .env.example .env.local
python scripts/serve.py
```

ثم افتح `http://localhost:8000`. إذا منعت سياسة PowerShell تفعيل البيئة، استخدم `.\.venv\Scripts\python.exe` بدل `python` في الأوامر؛ لا تحتاج لتغيير سياسة النظام.

### Linux / macOS / WSL

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm ci
npm run build
cp .env.example .env.local
python scripts/serve.py
```

إذا أردت تشغيل النسخة المبنية دون تعديل الواجهة، يمكن تخطي `npm ci` و`npm run build` واستخدام `dist/` المرفق.

## رحلة المؤسس

1. أنشئ حسابًا بموافقة معالجة منفصلة. يمكن استعمال مساحة التجربة الاصطناعية المحلية لمدة 24 ساعة لاستكشاف التدفق دون بيانات حقيقية؛ هذه الميزة معطلة في وضع الإنتاج.
2. اكتب البلد والمدينة والشريحة والمرحلة ونموذج العمل وموارد الفريق. البلد المستهدف هو أساس البحث، وليس بلد الحاضنة.
3. الجولة الأولى تختار **36 سؤالًا** موزعة على المحاور العشرين. يظهر سؤال واحد، ويمكنك المتابعة لاحقًا. يحتفظ المتصفح بمسودة الإجابة حتى الإرسال، ثم تحفظ في الحساب مشفّرة. لا تستخدم جهازًا مشتركًا لإجابات سرية؛ امسح المسودات عند الخروج.
4. «لا أعرف» تعني قيمة مجهولة، ولا تعني درجة صفر. «غير منطبق» تحتاج سببًا ولا تستبعد المحور كله تلقائيًا.
5. أضف الأدلة المنقحة، وأدخل المالية مع الفترة والعملة والوحدة والمصدر. يرفض المحرك استخدام عملات أو فترات غير متجانسة في الصيغة نفسها.
6. راجع التعارضات. مثلًا: 10 عملاء × وحدة واحدة × سعر 100 ينتج 1,000؛ إذا ذكرت إيرادًا 5,000، يظهر تنبيه ولا نعدّل أي مدخل بصمت.
7. شغّل التحليل. في الوضع الافتراضي يعمل المحرك الحتمي محليًا، ويظهر أن البحث الخارجي لم يُنفّذ.
8. راجع التقرير والمحاور والتوصيات وسجل الادعاءات. نزّل PDF أو JSON، وتابع المهام في 7 و30 و60 و90 يومًا.
9. أنشئ تشخيص متابعة من مساحة المؤسس. يمكنك نسخ التصريحات السابقة، لكن الأدلة والمراجعات لا تنتقل على أنها تحقق جديد.
10. قارن الشركة مع نفسها. إذا تغيرت المنهجية أو المرحلة أو السوق، تُحجب الفروق العددية ويُعرض سبب عدم قابلية المقارنة.

## البرنامج والمرشدون

أنشئ مديرًا محليًا؛ ستطلب الطرفية كلمة مرور، ولا تطبعها:

```bash
python scripts/manage.py create-admin --email manager@your-incubator.example --name "Program manager"
```

حسابات التسجيل العادي **لا تحصل على صلاحية مدير**. المدير ينشئ رمز دعوة لمؤسس أو مرشد، ثم يعيّن مرشدًا لكل شركة وافقت على المشاركة. المؤسس داخل البرنامج يرى شركته فقط؛ المرشد يرى الشركات المعينة له فقط، ومدير البرنامج يرى الشركات التي وافقت على المشاركة. يستطيع المدير مراجعة المؤشرات والمصادر، ولا يستطيع تعديل إجابات المؤسس.

من إعدادات المدير غيّر اسم المنصة ولونها وشعار PNG/JPEG. الشعار يقبل `data URL` أو أصلًا محليًا تحت `/assets/`. لا تُستخدم صور أو تتبعات خارجية تلقائيًا. إعداد الهوية يحفظ في قاعدة البيانات.

## البيانات الاصطناعية

```bash
python scripts/manage.py demo
```

اختر كلمة مرور للاختبار عبر الطرفية. سيُنشأ مدير ومرشد وثلاثة مؤسسين: `manager@demo.invalid` و`mentor@demo.invalid` و`marketplace@demo.invalid` و`services@demo.invalid` و`saas@demo.invalid`.

كل الحالات موسومة بأنها اصطناعية. أرقام حالة السوق متعدد الأطراف جاءت من الحالة المرفقة: 30 طلبًا، وإيراد مصرح به 750,000 YER، وتكلفة متغيرة 660,000 YER. ناتج المساهمة 90,000 YER هو **حساب داخل حالة اصطناعية**؛ ليس دليلًا عن سوق اليمن. الفرق بين GMV وصافي إيراد المنصة يحتاج مراجعة قبل استخدام أرقام شركة حقيقية.

## الذكاء الاصطناعي والبحث الحي

الموصلات البرمجية لـOpenAI Responses وAnthropic Messages مكتوبة في `backend/app/providers.py`، لكن **لم تُرسل طلبات مدفوعة ولم يُنشأ مفتاح API ولم يُختبر الاتصال الحي** في هذه النسخة. الإعداد الافتراضي `AI_PROVIDER=offline`.

للتفعيل بعد اختيار حسابك ومزودك، ضع المفتاح في متغير بيئة للخادم أو ملف `.env.local` المستبعد من النشر، وحدد:

```dotenv
AI_PROVIDER=openai
AI_MODEL=YOUR_AUTHORIZED_MODEL_ID
AI_MAX_OUTPUT_TOKENS=1800
AI_MONTHLY_BUDGET_USD=YOUR_APPROVED_BUDGET
AI_REQUEST_RESERVATION_USD=YOUR_CONSERVATIVE_PER_REQUEST_RESERVATION
```

اسم متغير مفتاح OpenAI هو `OPENAI_API_KEY`، وAnthropic هو `ANTHROPIC_API_KEY` عند اختيار `AI_PROVIDER=anthropic`. لا تضع المفاتيح في الواجهة أو ملفات عامة. تحقق من صلاحية النموذج للبحث وشروط الاحتفاظ بالبيانات قبل إدخال بيانات حقيقية. يمكن توفير المفتاح عبر مسار إعداد آمن في جلسة لاحقة، دون مشاركته نصًا في المحادثة.

الحجز المالي يحتسب كل محاولة حجزًا كاملًا حتى عند فشل HTTP، منعًا لتكرار محاولات قد تكون مدفوعة. هذا **سقف داخلي مبني على حجز تقديري وليس ضمانًا لفاتورة المزود**. توجد حدود فعلية لعدد الطلبات والرموز واستدعاءات البحث؛ اضبط أيضًا سقف الإنفاق على حساب المزود وفق أسعاره الحالية. الحد الأقصى للتحليل البحثي أربعة طلبات مرتبة: محلي، إقليمي، مماثل، عالمي؛ وطلب تفسير واحد اختياري.

المؤسس يرى نطاق البحث العام قبل تشغيله: البلد والمدينة والقطاع ونموذج العمل والمنطقة المقارنة فقط. لا تُرسل إجابات الشركة أو ماليتها أو ملفاتها في البحث. تحليل AI منفصل، ويستقبل المقتطفات التي كتبها المؤسس وسمح بإرسالها فقط. المستندات لا تدخل تلقائيًا في AI أو RAG. لا توجد بيانات كتب أو قواعد مدفوعة منسوخة إلى النظام.

نتائج البحث التي يسندها المزود بروابطه تبقى **مرشحة غير متحقق منها** حتى مراجعة شخص مخول. ترفض الروابط غير المسندة والحالات غير المناسبة للمقارنة. لا تتحول أسماء الشركات إلى منافسين متحقق منهم دون مصدر ومراجعة وحدود مقارنة. يحتفظ النظام بالمصادر المتعارضة وحداثتها.

## الحسابات والتقييم

- الحسابات المالية من دوال `Decimal` في Python، مستقلة عن AI. المدخل الفارغ يظل `null`.
- كل صيغة تعرض المدخلات والمصدر والفترة والعملات وتصنيفها: محسوب أو تقدير بافتراضات.
- لا LTV تلقائي دون رصد مجموعة واحتفاظ فعليين. وحتى النموذج الاسترشادي للاحتفاظ ثابت الانسحاب موسوم بحدوده.
- لا TAM/SAM/SOM تلقائي من نسب سوق عشوائية. يلزم عدد مشترين ووحدات وإنفاق سنوي ومصادر وسنة متجانسة وقدرة بيع وتحويل.
- التقييم يبدأ بالمؤشرات المئة، ثم يُجمع إلى عشرين محورًا. كل إجابة ترتبط بمؤشر واحد محدد، ولا ترفع خمسة مؤشرات في وقت واحد.
- تصريح مؤسس ذو محتوى يُسند مبدئيًا إلى درجة 1 في مؤشّره فقط. الدرجات 2–4 تتطلب مرشدًا ودليلًا وتعليلًا. لا تفسّر «تغطية التقييم» بأنها تحقق مستقل؛ تظهر تغطية مراجعات المرشد منفصلة.
- يُحجب تقييم المحور تحت 60% تغطية لمؤشراته المنطبقة. وتُحجب الدرجة الكلية تحت 60% من وزن المحاور القابلة للتقييم أو عند وجود أقل من عشرة محاور مقيمة.
- الأوزان الأصلية محفوظة. المنهجية أولية وغير معايرة بنتائج الشركات؛ الدرجة ليست احتمال نجاح.

## الاختبارات

```bash
python -m unittest discover -s backend/tests -v
python -m unittest discover -s specification/06_tests -v
npm run build
```

الحالات تشمل فكرة وإيرادًا مبكرًا للخدمات وSaaS والسوق متعدد الأطراف؛ بيانات ناقصة، تضارب أرقام، عزل مستأجرين ومؤسسين، صلاحيات وموافقة، CSRF، حماية ملفات، انقطاع البحث، حقن تعليمات كنص غير موثوق، ومهام قابلة للاستئناف. الاختبارات الاصطناعية لا تعوّض تجربة 3–5 مؤسسين حقيقيين ومراجعة مرشد مستقل.

ملفا PDF اصطناعيان بالعربية والإنجليزية موجودان تحت `output/pdf/`. تقرير الحالة المنظمة تحت `fixtures/`. ملف `docs/ACCEPTANCE_REPORT.md` يميّز PASS/FAIL/NOT RUN لكل بند من ملف القبول الأصلي.

## التخزين والنسخ الاحتياطي

في التشغيل المحلي تنشأ `.data/` وفيها SQLite WAL، ملفات مشفّرة، ومفتاح تطوير محلي بصلاحية ملف 0600. لا تشارك هذا المجلد أو تحفظه في Git. فقد المفتاح يفقد القدرة على فك البيانات. الإنتاج يحتاج مفتاحًا ثابتًا خارج المصدر، نقل TLS، وسياسة نسخ احتياطي وحذف مناسبة.

```bash
python scripts/manage.py backup /absolute/private/path/backup-2026-11-12
python scripts/manage.py verify-backup /absolute/private/path/backup-2026-11-12
```

ينسخ الأمر قاعدة البيانات وملفات الأدلة ومفتاح التطوير إن كان موجودًا. افصل نسخة المفتاح واحمها في بيئتك. تحقق النسخة يختبر سلامة قاعدة البيانات وفك عينة؛ **تمرين استعادة بيئة كاملة منفصل**.
